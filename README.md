# Edumerge Student Support & Ticket Management

A working prototype for **Assignment 4 — Student Support & Ticket Management** from the Edumerge Product Engineering assessment.

## What is included
- Student ticket creation
- Staff/admin ticket queue
- Role-based access: student, staff, admin
- Status workflow: Open → In Progress → Pending → Resolved → Closed
- Priority: Low / Medium / High / Critical
- Category-based SLA calculation
- SLA breach detection
- Ticket assignment/reassignment
- Comments and staff-only internal notes
- Activity/audit history
- Staff dashboard with workload and SLA metrics
- Search and filters
- SQLite database with automatic demo seed data
- Responsive browser UI

## Run locally
Requirements: Python 3.10+

```bash
python -m venv .venv
# Windows
.venv\\Scripts\\activate
# macOS/Linux
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --reload
```

Open: http://127.0.0.1:8000

## Architecture
Browser UI → FastAPI REST API → SQLAlchemy → SQLite.

The prototype intentionally uses SQLite so the evaluator can run it with no external database. PostgreSQL can be substituted later by changing the SQLAlchemy connection URL.

## Important product assumptions
1. Students create tickets; staff/admin manage them.
2. SLA starts when the ticket is created and is based on category.
3. Internal notes are visible only to staff/admin.
4. Resolved tickets can remain in the system for history and can be closed by staff.
5. A ticket may be unassigned while waiting in the queue.

## Validation / edge cases
The API validates authentication, role permissions, categories, status values, priority values and staff assignees. Students cannot read other students' tickets or create internal notes. Active tickets are checked dynamically for SLA breach.
